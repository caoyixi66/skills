## 2026-08-05 QSSI `systemimage` 的 CTS 平台版本误报

状态：已确认，适用源码工作区 `/home/new_ssd1/caoyixi/workspace/android/ef930_2`。

### 现象与根因

执行 `xgd_build.sh -dqm systemimage` 时，曾在 Kati 配置阶段报：

```text
Could not find version "13" in CTS platform version file:
cts/tests/tests/os/assets/platform_versions.txt
```

当时源码的 `qssi14/build/make/core/version_defaults.mk` 中 `PLATFORM_VERSION_LAST_STABLE := 14`，且 `platform_versions.txt`、`platform_releases.txt` 均为 `14`；它们本身一致，不应为了消除报错而补写 `13`。

根因是启动构建的 shell 已导出旧值 `PLATFORM_VERSION=13`。`version_util.mk` 仅在该变量未定义时才从 `PLATFORM_VERSION_LAST_STABLE` 计算版本，因此旧环境值覆盖了源码默认的 `14`。`cts.mk` 随后将有效值 `13` 与只含 `14` 的 CTS 清单比较并失败。用预设 `PLATFORM_VERSION=13` 的干净 shell 可以稳定复现；清除该变量后，`lunch qssi-userdebug` 解析为 `PLATFORM_VERSION=14`。

切换到正确环境后的构建日志还出现：

```text
Environment variable PLATFORM_VERSION was modified (13 => 14), regenerating...
```

这说明已有 `out/` 记录过 Android 13 的环境；Soong 会重新生成依赖图。它是环境变化的证据，不表示需要清理源码或修改 CTS 文件。

### 处置与验证

从工作区根目录使用：

```bash
unset PLATFORM_VERSION PLATFORM_VERSION_LAST_STABLE TARGET_PLATFORM_VERSION PLATFORM_VERSION_CODENAME
./xgd_build.sh -dqm systemimage
```

2026-08-05 的该命令以状态 `0` 完成，耗时 8 分 10 秒，生成：

| 产物 | 路径 | 验证 |
|---|---|---|
| QSSI system image | `qssi14/out/target/product/qssi/system.img` | 2026-08-05 21:14:46，大小 1,178,726,400 bytes |
| update_engine staging binary | `qssi14/out/target/product/qssi/system/bin/update_engine` | 含 `dynamic-partition-metadata-updated-target-slot` 和 `Preparing partitions for new update.` 字符串 |

构建中出现的 license metadata、旧 sepolicy 预编译文件 `cat` 失败等 warning 在本次成功构建中仍存在，不能仅凭这些 warning 判定 `systemimage` 失败；应以最终 `build completed successfully`、返回码和目标产物为准。

### shell 边界

`. xgd_build.sh ...` 是在当前 shell source 脚本，脚本及其 `source build/envsetup.sh`、`export`、`lunch` 的环境副作用可能留在该终端。`./xgd_build.sh ...` 在子进程执行，脚本结束后不会把它自身新增的环境长期留在当前终端，因此是较稳妥的日常入口。

但 `./` 仍会继承父 shell 已经导出的变量，不能单独防止本问题。只要父 shell 中仍有 `PLATFORM_VERSION=13`，子进程同样可能把它传入 Android build。故在切换 Android 工作区、版本或 lunch 目标后，必须先执行上面的 `unset`，或在新的干净 shell 中构建。

重新验证条件：`version_defaults.mk`、CTS 平台清单、`xgd_build.sh`/`build/envsetup.sh`、Android 大版本或构建环境传递方式发生变化后，重新检查有效的 `PLATFORM_VERSION` 与 CTS 清单。
