# EF930 概览

EF930 按一个机型统一管理。历史上出现过不同源码目录名称，但这些只是同一机型在不同时期或用途下的工作区，不建立分支资料、不分别归类。

## 资料范围

| 任务方向 | 读取重点 | 状态 |
|---|---|---|
| repo、manifest、源码结构、构建入口 | `工作区与构建.md`、`Git与提交.md` | 已确认历史事实，操作前重验 |
| 技术专题、功能模块和复杂问题 | `技术专题索引.md` | 按实际任务路由 |
| VAB、snapshot/COW、payload、Recovery OTA | `专题/` 下的对应资料 | 已确认历史事实，操作前重验 |
| 历史故障与适用边界 | `已知问题.md`、`问题/` | 先确认是否命中当前场景 |

## 使用规则

1. 用户给出当前目录时，先检查当前源码工作区的目录和源码结构。
2. 用户只给出 OTA 日志时，先判定包类型与调用链，再选择资料。
3. 用户只说“EF930”而没有路径、日志或模块时，先提出最小澄清问题或做只读路径探测。
4. 所有路径、分支、产物时间和设备状态均为实时信息，历史资料不替代探测。
5. 先读 `技术专题索引.md`，再按表中资料位置进入专题或功能模块；不要靠文件名猜测结论。
