# CT20 安全芯片主动上报链路

状态：已确认  
适用范围：CT20 安全芯片 SPI IRQ、内核 spidev 驱动、netlink 与 report_monitor_service  
创建日期：2026-08-06

## 模块边界

| 项目 | 内容 |
|---|---|
| 用户可见能力 | 安全芯片经 SPI IRQ 主动上报事件时，通知用户态 report-monitor 获取/处理 report；异常分支可向 NFC netlink 发送 `SpiNFCReport` |
| 涉及层次 | 安全芯片/IRQ 电气行为（未验证） -> 内核 spidev 驱动 -> workqueue/kworker -> netlink -> native `report_monitor_service` -> DDI/SPI 查询 |
| 不覆盖的范围 | IRQ 线的实际电气时序、固件协议语义、`nci_discovery` 业务规则、每一个硬件事件是否一对一处理，以及驱动的内存所有权 |
| 证据来源 | 2026-08-06 重读 `vendor/nexgo/kernel/nexgo_drivers/spidev-sp/spidev-xgd.c` 与 `vendor/nexgo/system/ddiservice/report_monitor/report_monitor_service.c` |

## 已确认链路

| 环节 | 已确认事实 | 状态 | 证据与重新验证条件 |
|---|---|---|---|
| IRQ 注册 | SPI IRQ GPIO 经 `request_irq(..., k21_interrupt, IRQF_TRIGGER_FALLING, ...)` 注册为下降沿中断 | 已确认 | `spidev-xgd.c:3918-3921`；设备 DTS/GPIO 变化后重查 |
| 硬中断上半部 | `k21_interrupt()` 执行 `udelay(10)`，读取 GPIO；电平为 1 时 `atomic_inc(&report_event)`，随后 `queue_work(spidev_wq, &spidev_work)` 并返回 `IRQ_HANDLED` | 已确认 | `spidev-xgd.c:2701-2722`；该函数不直接执行完整 SPI 读取 |
| 工作项初始化 | `spidev_work` 由 `INIT_WORK(&spidev_work, spidev_irq_work_fun)` 绑定回调；`spidev_wq` 由 `create_singlethread_workqueue("spi_get_data")` 创建 | 已确认 | `spidev-xgd.c:3820,4211`；workqueue 是队列和 kworker 执行机制，不是回调函数自身的永久等待循环 |
| 可睡眠下半部 | `spidev_irq_work_fun()` 读取 `report_event`；若系统仍在 resume 过渡，最多 10 次 `msleep(100)`；随后按 GPIO/NCI 状态发送通知或读取 SPI 数据 | 已确认 | `spidev-xgd.c:3553-3599`；`msleep()` 位于 kworker/process context，不应移到硬中断函数 |
| 内核到用户态通知 | `netlink_send_simple()` 构造字符串 `report`，向组 1 广播；内核/服务源码均定义 `NETLINK_USER=31` | 已确认 | `spidev-xgd.c:3292-3317,203`；`report_monitor_service.c:36,799` |
| 用户态处理 | `report_monitor_service` 经 `recvmsg()` 收到包含 `report` 的消息后调用 `spi_ddi_get_report_event()` 获取实际 report 数据 | 已确认 | `report_monitor_service.c:566-590`；`report` 是通知字符串，不是完整 report payload |
| NFC 异常通知 | 当 DDI 查询失败时，服务调用 `netlink_send_nfc_report()`；该服务和内核驱动均定义 `NETLINK_NFC=29`，用户态发送 `SpiNFCReport` | 已确认 | `report_monitor_service.c:35,235-264,584-590,819`；该异常路径的内存问题见问题页 |

## 未覆盖边界

| 项目 | 当前状态 | 所需证据 |
|---|---|---|
| 硬件 IRQ 高频的根因 | 待验证 | 原理图/芯片协议、GPIO 时序、同时间窗口的 IRQ 和 DDI 错误计数 |
| 每个 IRQ 的精确处理次数 | 待验证 | 当前工作函数仅按 `value_report` 是否非零分支并清零计数；需协议和事件统计证明一对一语义 |
| 内核驱动是否泄漏 | 待验证 | 内核 slab/kmem、驱动分配路径、重复负载下的内核内存时间序列 |
