# OpenGrok 跨项目检索

## 适用场景

当当前项目源码不足以判断某个厂商实现、历史移植方案或同类设备行为时，使用内部 OpenGrok 进行跨项目对照。

## 工作流

1. 先确认当前项目中正在生效的文件、分支和源码层。
2. 用稳定标识检索：函数名、属性名、错误码或明确路径片段。
3. 限定项目和路径，排除测试、第三方代码和无关 App 命中。
4. 下载或打开命中的原始源码，再阅读准确上下文。
5. 将 OpenGrok 结果视为参考实现，最终结论必须回到当前源码工作区、构建产物或设备日志。

## 查询规则

| 建议 | 原因 |
|---|---|
| 优先使用 API/结构化结果 | 便于筛选项目、路径和行号 |
| 避免带大量标点的完整字符串 | 索引分词可能导致漏检 |
| 小范围、低输出量检索 | 防止返回过大或超时 |
| 先符号后路径 | 先找到语义，再确认实际实现 |

## 安全规则

- 从当前已配置、已授权的 OpenGrok 环境获取认证；不得在文档、脚本或示例中固化访问令牌。
- 不在最终答复中泄露认证头、令牌、Cookie 或内部凭据。
